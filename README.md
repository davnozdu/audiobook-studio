# Audiobook Studio

Нативное приложение для macOS 14+ на Apple Silicon. Интерфейс — SwiftUI,
проверенный движок Qwen/MLX и Silero встроен в `.app` вместе с Python, FFmpeg,
словарями и фоновой музыкой. Отдельная установка Python/Homebrew не требуется.
При первой сборке книги скачиваются только TTS-модели (с проверкой размера/SHA256).

## Работа с книгой

1. В настройках введите Ollama API key. Он живёт только в памяти текущего сеанса.
2. Выберите EPUB и папку результатов, нажмите «Определить персонажей и расставить роли».
3. Нажмите «Определить характеры персонажей». DeepSeek V4.1 Flash последовательно
   анализирует контекст каждого персонажа. Веб-поиск Ollama включается отдельно.
4. Отредактируйте возраст, характер, привычки, манеру речи и описание голоса.
   Основания и предположения доступны в карточке. LLM не меняет ID и разметку текста.
5. Для любой роли, включая рассказчика, можно загрузить собственный образец:
   чистая запись одного голоса 3–30 секунд и точный текст, произнесённый в записи.
   Он заменит VoiceDesign для этой роли; остальные голоса будут сгенерированы.
6. Выберите штатную музыку или свой файл. Громкость по умолчанию 5%, трек зацикливается
   до конца книги. Музыку можно отключить. Выбранный трек копируется в проект книги.
7. «Собрать аудиокнигу и наложить на EPUB» создаст `result/book.m4b` и
   `result/book-read-along.epub`. Синхронизация/подсветка по предложениям требует
   EPUB3-читалки с Media Overlays. Безмузыкальная речь сохраняется отдельно.

Нормализация текста, словарь + Silero, последовательная загрузка VoiceDesign и Base,
нормализация громкости по ролям и контроль длительности музыки сохранены из CLI.
Неопределённые роли блокируют озвучку; разметка доступна в `roles/review.json` и
`roles/manifest.json` для проверки. Первая версия ещё не включает редактор разметки
реплик в самом GUI. Карточки и свои образцы сохраняются в проекте книги;
временные сгенерированные образцы удаляются после синтеза.

Скорость отображается в аудиосекундах на секунду синтеза (например 1,3×).
Прогноз оставшегося синтеза учитывает последние 12 фрагментов и объём оставшегося
текста. До первых замеров оценка отсутствует. Создание образцов, загрузка моделей,
нормализация и упаковка показываются отдельными этапами и не входят в этот прогноз.
Все обращения к LLM и веб-поиск строго последовательны. Запускается только одна задача.

## Сборка и обновления

GitHub Actions собирает автономный ARM64 `.app` при каждом push в `main`.
Архив доступен в артефактах Actions; тег `v0.1.0` создаёт GitHub Release.
В релиз включаются ZIP и подписанный `appcast.xml`. Sparkle проверяет Ed25519-подписи
архива и ленты, поддерживает автоматическую проверку обновлений и установку.
Книги, пользовательские образцы, ключи, результаты и модели не хранятся в Git.

Постоянный ключ обновлений: публичная часть в `sparkle-public-key.txt`, закрытая —
в GitHub Actions secret `SPARKLE_PRIVATE_KEY`. Резервная копия в `.private/sparkle.key`
исключена из Git; сохраните её отдельно. Не генерируйте новый ключ для каждого релиза.
Этот ключ удостоверяет обновления, но не заменяет Apple Developer ID.
Текущие сборки имеют ad-hoc code signature, без нотарификации Apple.
Первый запуск может потребовать разрешения в настройках безопасности macOS.

Для разработчика: `brew install ffmpeg`, затем `bash scripts/package.sh`.
Тесты: `python3 -m unittest discover -s tests -v`.
Снимок исходного движка и его commit находятся в `backend/engine/UPSTREAM.txt`.

## Зависимости

SwiftUI/AppKit, Sparkle 2.9.6, Python Build Standalone (CPython 3.11), Qwen3-TTS,
MLX Audio, Silero Stress/PyTorch, FFmpeg, EbookLib, BeautifulSoup.
См. `backend/engine/THIRD_PARTY.md`; лицензии установленных Python-пакетов остаются
в их `dist-info` внутри приложения. FFmpeg собирается из Homebrew; его конфигурация
и соответствующие исходники доступны через `brew info --json=v2 ffmpeg` и
https://github.com/Homebrew/homebrew-core/blob/HEAD/Formula/f/ffmpeg.rb.
Штатная композиция «Свет лампы и страницы» включена по разрешению владельца проекта.
