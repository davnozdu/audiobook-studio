# Audiobook Studio

Нативное приложение для macOS 15+ на Apple Silicon. Интерфейс и движок — Swift,
генерация Qwen3-TTS работает через MLX Swift, ударения Silero — через C++/libtorch.
Python, pip и виртуальных окружений в приложении нет. FFmpeg, словари, модель
ударений и семь фоновых композиций входят в `.app`. При первом использовании
скачиваются только модели Qwen, с проверкой размера и SHA256.

На GitHub Python применяется только как инструмент сборки: экспортирует Silero
в TorchScript и упаковывает зависимости. Чистый пакет проверяется офлайн с пустой
домашней папкой: запускаются нативные Metal-ядра и загружаются обе модели ударений.
Проверка не синтезирует речь и не обрабатывает пользовательские книги.

## Работа с книгой

1. В настройках введите Ollama API key. Он сохраняется в системной Связке ключей
   macOS; ключ и настройки сохраняются между перезапусками и обновлениями приложения.
2. Выберите EPUB и папку результатов, нажмите верхнюю кнопку «Собрать автоматически»
   с волшебной палочкой: разметка, характеры, модели и сборка выполняются подряд.
   Модель уточняет неопределённые реплики; оставшиеся получают «Прочие голоса» без
   остановки сборки. Эти назначения сохраняются с низкой уверенностью для последующей правки.
3. Для пошаговой работы нажмите «Определить персонажей и расставить роли»:
   характеры тоже заполнятся автоматически. Рассказчик получает стандартный шаблон.
   Кнопка «Определить характеры персонажей» повторяет анализ. Запросы DeepSeek
   выполняются последовательно; веб-поиск Ollama включается отдельно.
4. Персонажи отображаются общим списком раскрывающихся карточек. При желании уточните возраст, характер, привычки, манеру речи и описание голоса.
   Основания и предположения доступны в карточке. LLM не меняет ID и разметку текста.
5. Для любой роли, включая рассказчика, можно загрузить собственный образец:
   чистая запись одного голоса 3–30 секунд и точный текст, произнесённый в записи.
   Он заменит VoiceDesign для этой роли; остальные голоса будут сгенерированы.
6. Выберите одну из семи штатных композиций или свой файл. Громкость по умолчанию 5%, трек зацикливается
   до конца книги. Музыку можно отключить. Выбранный трек копируется в проект книги.
7. «Собрать аудиокнигу и наложить на EPUB» создаст `result/audiobook.m4b` и
   `result/audiobook.epub`. Синхронизация/подсветка по предложениям требует
   EPUB3-читалки с Media Overlays. Безмузыкальная речь сохраняется отдельно.

«Генератор голосов» в боковой панели работает независимо от книги:
опишите голос, напишите тестовый текст, выберите вариант и запустите конструктор.
Для русских описаний используется последовательный запрос LLM, который переводит
режиссуру на английский. Английское описание без карточки можно передать напрямую.
Загружается только VoiceDesign. После генерации можно прослушать пробу и сохранить
WAV вместе с JSON, содержащим точный текст и описание. При последующей загрузке
такого WAV в карточку персонажа текст подхватывается из соседнего JSON автоматически.
У каждой роли также есть «Прослушать образец»: свой загруженный голос воспроизводится
сразу; для нейросетевого голоса создаётся проба по текущему описанию. Эти пробы можно
сохранять отдельно или закреплять кнопкой «Использовать для персонажа»; сгенерированные голоса полной сборки сохраняются внутри проекта. Прослушивание происходит прямо
в приложении; повторное нажатие останавливает запись.

Нормализация текста, словарь + Silero, последовательная загрузка VoiceDesign и Base,
нормализация громкости по ролям и контроль длительности музыки сохранены из CLI.
Неопределённые роли автоматически уточняются моделью; оставшиеся получают «Прочие голоса». В GUI можно проверить реплики, найти их
по тексту и изменить говорящего. Изменяется только назначение роли; текст и
привязки EPUB сохраняются. Карточки и свои образцы сохраняются в проекте книги;
сгенерированные образцы сохраняются для повторной сборки; изменение описания голоса создаёт новый образец.
Возраст звучания, характер, привычки, манера речи и описание тембра из карточки
вместе преобразуются в английскую инструкцию VoiceDesign. Изменение любого из этих
полей отменяет сохранённую инструкцию и образец. Реплики остаются на русском.
Инструкция и её связь с текущей карточкой сохраняются внутри проекта.
Собственный загруженный образец задаёт голос вместо VoiceDesign.

Скорость отображается в аудиосекундах на секунду синтеза (например 1,3×).
Прогноз оставшегося синтеза учитывает последние 12 фрагментов и объём оставшегося
текста. До первых замеров оценка отсутствует. Создание образцов, загрузка моделей,
нормализация и упаковка показываются отдельными этапами и не входят в этот прогноз.
Все обращения к LLM и веб-поиск строго последовательны. Запускается только одна задача.

В настройках можно включать значок в Dock и верхней панели macOS. Один из них
всегда остаётся доступным. Из верхней панели открывается окно и доступна остановка
работы. Переключатель «Обычный / Фоновый» работает во время сборки: macOS снижает
приоритет CPU и ввода-вывода, а прогноз времени учитывает измеренную скорость.
Это не ограничение памяти или мощности GPU. Настройки присутствия и приоритета
сохраняются между запусками. Иконка приложения: `assets/AppIcon.png`, `assets/AppIcon.icns`.

## Сборка и обновления

GitHub Actions собирает автономный ARM64 `.app` при каждом push в `main`.
Архив доступен в артефактах Actions; тег `vX.Y.Z` создаёт GitHub Release.

Закрытие проекта, смена книги и выход предлагают сохранить проект, закрыть без сохранения или отменить действие. До завершения первоначального распознавания сохранение проекта недоступно; рабочие файлы остаются на диске.

Предварительная длительность речи рассчитывается по 12 знакам в секунду. Оценка времени синтеза использует предыдущие замеры на этом компьютере, а при их отсутствии — диапазон скорости 0,5–2×. Во время генерации оценка уточняется по последним 12 фрагментам. Загрузка моделей, создание голосов и упаковка требуют дополнительного времени.

Повторное прослушивание неизменённого образца использует WAV из кеша. Изменение текста, профиля, образца речи или seed требует новой генерации. Отдельные реплики тоже кешируются: ключ включает текст для синтеза, хеш и расшифровку голоса, seed и параметры генерации. Повреждённый WAV пересоздаётся. При полностью сохранённой озвучке модель чтения не загружается в RAM. Проверенные файлы моделей не хешируются повторно до изменения их файловых метаданных. Модели освобождаются до упаковки книги; кеш буферов MLX ограничен, а завершение отдельного процесса движка освобождает его память.
В релиз включаются ZIP и подписанный `appcast.xml`. Sparkle проверяет Ed25519-подписи
архива и ленты, поддерживает автоматическую проверку обновлений и установку.
Книги, пользовательские образцы, ключи, результаты и модели не хранятся в Git.

Постоянный ключ обновлений: публичная часть в `sparkle-public-key.txt`, закрытая —
в GitHub Actions secret `SPARKLE_PRIVATE_KEY`. Резервная копия в `.private/sparkle.key`
исключена из Git; сохраните её отдельно. Не генерируйте новый ключ для каждого релиза.
Этот ключ удостоверяет обновления, но не заменяет Apple Developer ID.
Текущие сборки имеют ad-hoc code signature, без нотарификации Apple.

Громкость ролей выравнивается к −20 LUFS. Если пики этого не позволяют, общий уровень понижается, но не ниже −23 LUFS; оставшиеся пики ограничивает лимитер при кодировании M4B, без сдвига времени. Роли короче трёх секунд измеряются по повторённой записи. M4B получает обложку книги (JPEG или PNG из EPUB) и теги album и genre; обложка добавляется и в итоговый EPUB.

Текст книги читается из абзацев, заголовков, списков, цитат, ячеек таблиц и блоков div/section без вложенных абзацев. Текст вне таких блоков останавливает извлечение, чтобы не потерять его. Свои образцы голоса хранятся относительно папки проекта, поэтому перенесённый проект продолжает работать.

После сборки удаляются промежуточные полные WAV нормализации и музыки. Отдельные реплики и их кеш, голоса, книга и итоговые M4B/EPUB сохраняются для дальнейшего редактирования. Каждая операция получает отдельную временную папку, которую оболочка удаляет и после принудительной остановки движка. Повторные сборки не создают архивов предыдущих рабочих WAV.

Несколько предложений в пределах одной размеченной роли объединяются в блок до 240 знаков; роли и привязки к тексту сохраняются. Это сокращает число отдельных запусков синтеза. Обрамляющие тире диалога убираются только из текста для модели. При пустом результате выполняются максимум три попытки с разными seed, без подмены персонажа или пропуска реплики. После трёх неудач ошибка содержит ID и текст реплики; готовые фрагменты остаются в кеше.

Ударения ставятся знаком U+0301 после ударной гласной, как ожидает модель Ru-Stress-CF: сначала фразы и омографы Silero по контексту, затем словари Supertonic и исключения Silero, для остальных слов — нейросеть Silero. Буква ё восстанавливается в тексте для синтеза по словарям, исключениям, омографам (все/всё, осел/осёл, чем/чём) и предсказанию Silero; текст книги и EPUB не меняются. Слова через дефис («по-моему», «кто-то») сначала ищутся в словаре целиком. Односложные слова знак не получают. Проверке LLM передаются слова без ударения и омографы, решённые Silero неуверенно; для омографа принимается только один из подготовленных вариантов.

Перед разметкой ролей каждый абзац делится на реплики и авторские слова по тире после знака препинания и по кавычкам. Модель только называет говорящего для каждого фрагмента: ремарки вроде «— сказал он» и «— обратился он к князю» читает рассказчик, а текст книги не может быть изменён. Ответ модели содержит лишь ID персонажей, поэтому разметка идёт быстрее и без повторов из-за неточно переписанного текста.

Сетевые сбои, HTTP 429 и ошибки сервера Ollama повторяются до трёх раз с паузами 5, 15 и 45 секунд; отклонённый ключ сообщается сразу. Ответ, не прошедший проверку, запрашивается повторно с текстом найденной ошибки. Другое написание имени уже известного персонажа становится псевдонимом, не меняя его личность. Основания карточки, которых нет в книге или в результатах поиска, отбрасываются. Если модель не определила говорящего или сервис не ответил, реплика получает «Прочие голоса». Проверка ударений через LLM необязательна: неверные слова и отсутствие ответа оставляют результат словаря и Silero.

Ответы LLM принимаются как обычный JSON или JSON в Markdown-блоке. Незавершённые, пустые и повреждённые ответы отклоняются с понятным сообщением; выполняются максимум три последовательные попытки. Непригодный ответ сохраняется локально в `llm-responses` проекта для диагностики, с удалённым ключом API. Формат API: [Ollama chat](https://docs.ollama.com/api/chat). Параметр `format` не отправляется в Ollama Cloud: облачный сервис [не поддерживает structured outputs](https://docs.ollama.com/capabilities/structured-outputs); JSON запрашивается инструкцией и проверяется приложением.
Первый запуск может потребовать разрешения в настройках безопасности macOS.

Для разработчика: Xcode с Metal Toolchain, затем `bash scripts/package.sh`.
ARM64-комплект FFmpeg берётся из проверенного архива предыдущей сборки;
устанавливать Homebrew или FFmpeg на компьютере пользователя не требуется.
Тесты ядра: `STUDIO_CORE_ONLY=1 swift test --package-path native`.
В `backend/engine` хранятся только данные для пакета: списки файлов моделей, правила
нормализации, словарь ударений и музыка.

## Зависимости

Нативный путь VoiceDesign приведён к `non_streaming_mode=True` официального Qwen: весь текст и EOS доступны модели до генерации звука. Проверяемая поправка к закреплённой Swift-библиотеке описана в [аудите](native/patches/README.md). При чтении обязательны веса speaker encoder и непустое конечное представление личности говорящего; его хеш сохраняется в журнале. Лимит аудио не сокращается эвристикой по числу токенов текста, а незавершённая реплика отклоняется. Прослушанный образец используется при сборке без повторного VoiceDesign, пока текст, карточка и seed не изменились. Кеш прежнего алгоритма инвалидируется, пользовательские записи сохраняются.

Голос создаётся в два этапа: VoiceDesign записывает образец с короткой английской инструкцией, затем Base клонирует этот образец. Инструкция отдельно описывает тембр и одну постоянную манеру речи; привычки переводятся в слышимые признаки без добавления слов, смешков или других звуков. Явно заданное старческое или измученное звучание не меняет биографический возраст персонажа. Новый формат инструкции инвалидирует старые сгенерированные образцы, сохраняя загруженные пользователем голоса. Во время чтения входные массивы всех образцов удерживаются до конца синтеза: кеш библиотеки, использующий адрес объекта, не должен принять другой образец за прежний. Хеш используемого образца каждого персонажа записывается в журнал. Схема соответствует [VoiceDesign → Clone](https://github.com/QwenLM/Qwen3-TTS#voice-design-then-clone); точность актёрской подачи требует прослушивания.

SwiftUI/AppKit, Sparkle 2.9.6, Qwen3-TTS, MLX Audio Swift, Silero Stress/libtorch, FFmpeg.
Лицензии нативных зависимостей включены в `Contents/Resources/licenses`. FFmpeg собирается из Homebrew; его конфигурация
и соответствующие исходники доступны через `brew info --json=v2 ffmpeg` и
https://github.com/Homebrew/homebrew-core/blob/HEAD/Formula/f/ffmpeg.rb.
Все семь штатных композиций включены по разрешению владельца проекта.

«Сохранить проект…» в меню «Файл» (⌘S) и главном окне создаёт один файл `.audiobookstudio`: книга, карточки и роли, загруженные голоса, выбранная музыка, настройки сборки и готовое аудио. Модели и API-ключ в файл не включаются. «Открыть проект…» (⌘O) распаковывает независимую рабочую копию: можно изменить голос и заново собрать книгу. Предыдущая сборка остаётся в папке `revisions` внутри проекта.

Пробы сгенерированных голосов автоматически воспроизводятся один раз и используют собственные реплики персонажа из книги: цель 120 знаков с пробелами, граница по слову или предложению до 150 знаков (примерно 10–13 секунд); короткие начальные реплики дополняются последующими репликами того же персонажа.

Перед ручной или автоматической сборкой открывается окно «Куда сохранить аудиокнигу?»: укажите место и имя новой папки для M4B и EPUB. Файл редактируемого проекта сохраняется отдельно через «Сохранить проект…». После сборки полный путь отображается в статусе и доступна кнопка «Папка аудиокниги».
